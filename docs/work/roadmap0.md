ZeroPad — 開発ロードマップ
設計方針確定
ZeroPadは「設定が簡単で、軽くて、確実に動く」ことに特化したWindows用OSSとして開発します。
ゲームパッドのイラスト、独自デザインのUI、アニメーションは不要です。Windows標準のコントロールを使い、設定項目を表形式で分かりやすく表示します。
1. 基本方針
項目	方針
対応OS	Windows 11 x64以降
言語	C++20
ビルド	CMake + MSVC
UI	Win32 API / Common Controls
入力取得	XInput
キーボード出力	SendInput
設定	自作cpptoml
配布	単一EXE、インストール不要
動作	タスクトレイ常駐
ライセンス	OSS、ライセンスは公開前に決定
Windows 10の一般向けサポートは2025年10月14日に終了しています。そのため、古いWindowsとの互換性維持は開発目標から外し、Windows 11を公式サポート対象とします。Windows 10のLTSCなど特別なサポート期間が残るエディションもありますが、ZeroPadとして対応を保証する必要はないと考えます。

開発原則
- 外部UIフレームワークを導入しない。
- キーボード変換に独自ドライバーを要求しない。
- 設定画面を開いていなくても変換を継続する。
- 通常の利用に管理者権限を要求しない。
- 変換エンジンとUIを分離する。
- 誤動作やキーの押しっぱなしを防ぐことを最優先する。
- 過度な抽象化、プラグイン機構、独自スクリプト言語を作らない。

5. cpptomlの扱い
リポジトリを確認したところ、taqu/cpptoml はメモリフットプリントの小ささを重視したTOML 1.0.0のリーダーで、cpptoml.cpp と cpptoml.h から構成されています。公開READMEの主要APIは TomlParser、TomlProxy です。


GitHub



重要なのは、現時点のREADMEでは読み込み機能が中心で、設定ファイルを書き戻すAPIを確認できないことです。
そのため、ZeroPadでは次の構成が合理的です。
config.toml
    |
    v
cpptoml (parser)
    |
    v
Config (typed C++ struct)
    |
    +----> Input Engine
    |
    +----> Win32 Settings UI
    |
    v
Minimal TOML serializer
    |
    v
config.toml


汎用TOMLライターを新しく作る必要はありません。ZeroPadが使う固定の設定項目だけを正しいTOML形式で出力する小さなシリアライザーで十分です。
これにより、既存のcpptomlを大きく改造せず、保守対象を増やさずに済みます。
6. v1.0.0の完了条件
機能の実装完了だけではなく、利用時の安定性をリリース基準にします。
分類	完了条件
入力	全対応ボタンが正しくキーに変換される
同時押し	複数ボタン・同一キー割り当てで破綻しない
安全性	切断・無効化・正常終了時にキーが解放される
UI	TOML編集なしですべての設定を変更可能
設定	保存・再起動・再読み込みが正常動作
復旧	コントローラー再接続後に自動復帰
常駐	設定画面を閉じても変換動作を継続
配布	インストーラー・管理者権限不要
性能	常駐メモリ10MB以下を目標に実測
品質	Windows 11実機での長時間テストを通過
SendInputによる入力を受け付けないアプリケーションまで完全対応を保証する必要はありません。通常のデスクトップアプリや対応ゲームでの動作を対象とします。
なお、Windowsによる強制終了など、プロセス自身が後処理できない状況まではキー解放を保証できないため、復旧手段も検討します。

8. 意図的に実装しないもの
ZeroPadの軽量性とシンプルさを維持するために、次は当面スコープ外とします。
- ゲームパッドのグラフィカルな配置図
- 独自UIレンダリングエンジン
- WebView / Electron / Qt
- クラウド設定同期やユーザーアカウント
- 自動更新サービス
- 仮想コントローラードライバー
- ゲームごとの自動検出とプロファイル切替
- 高度なマクロスクリプト機能
特に、UIで便利そうに見える機能の追加が、設定操作を複雑にするなら採用しないという判断基準が重要です。

9. 推奨する最初の実装順序
まずPhase 0〜1を最優先で作り、GUIより先に入力エンジンの信頼性を確立します。
最初のマイルストーン：A → Space

Windows 11でAボタンを押すとSpaceが押され、離すと解放される。ここを最小の動作確認単位とします。
次のマイルストーン：複数キーとアナログ入力

安定した変換エンジンを構築し、UIなしでもテストできるようにします。
最後のマイルストーン：一般ユーザーが使えるEXE

設定UI・タスクトレイ・保存機能を統合し、ZIPを展開するだけで利用できる状態にします。

ZeroPadでは、ライブラリやクラスを増やして拡張性を追求するよりも、入力変換・設定管理・Win32 UIの3つを小さく独立させる方が、長期的にも扱いやすい構成になると思います。
このロードマップなら、まず動くものを作り、その後に一般ユーザー向けの使いやすさを加えるという順序で、無理なくv1.0.0を目指せます。
